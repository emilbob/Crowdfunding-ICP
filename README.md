# Crowdfunding-ICP

An Internet Computer (ICP) smart contract (canister) for crowdfunding: create campaigns, contribute to them, track progress, and settle funds on completion. Written in TypeScript with [Azle](https://github.com/demergent-labs/azle), settling real tokens through an ICRC-1/ICRC-2 ledger.

## Overview

A Kickstarter-like decentralized crowdfunding platform. Campaigns have an owner, a goal amount and an end date. Only a campaign's creator can withdraw or delete it; anyone else can contribute. Contributions are real token transfers held by the canister until the campaign resolves:

- **Goal reached** → the owner calls `withdrawFunds` and the canister transfers the raised total (less the ledger fee) to them. One-shot.
- **Expired below goal** → each backer calls `refund` and gets their own contributions back (less the ledger fee).

### Campaign lifecycle

```
createCampaign ──> open ──> goal reached ──> withdrawFunds ──> settled
                     │
                     └────> expired below goal ──> refund (per backer)
```

## How contributions work (ICRC-2)

This canister does not take custody by magic — it pulls tokens using the ICRC-2 approve/transfer_from pattern. Contributing is **two steps**:

1. **Approve** the crowdfund canister as a spender on the ledger, for at least `amount + fee`.
2. **Call `contribute`**, which performs `icrc2_transfer_from` to move the tokens into the canister.

If step 1 is missing or too small, `contribute` returns a `LedgerError` explaining that.

## Getting started

### Prerequisites

- [Node.js](https://nodejs.org) 20 or newer
- [DFX](https://docs.internetcomputer.org/building-apps/getting-started/install) — the IC SDK. Azle's install step invokes `dfx`, so install DFX **before** running `npm install`.
- An ICRC-1/ICRC-2 ledger canister to settle against (the ICP ledger, or a local ledger for development)

### Installation

```bash
git clone https://github.com/emilbob/Crowdfunding-ICP.git
cd Crowdfunding-ICP
npm install
```

### Project structure

- `src/index.ts` — the canister: all methods, storage and ledger integration
- `dfx.json` — canister configuration for DFX
- `package.json` — dependencies and scripts
- `tsconfig.json` — TypeScript compiler options
- `LICENSE` — MIT License

The Candid interface is **generated by Azle at build time** (into `src/declarations/`), so there is no checked-in `.did` file to keep in sync.

### Tests

`npm run test:e2e` deploys a **real ICRC-1/ICRC-2 ledger** (downloaded from a pinned `dfinity/ic` release) plus this canister onto a running local replica, then exercises the full money path — approve, contribute, cap at goal, withdraw, refund guards, authorization and validation — asserting on **actual ledger balances**, not just return values.

```bash
npm run start      # replica must be running first
npm run test:e2e
```

The suite adds the ledger to `dfx.json` for the duration of the run and restores it on exit. The refund *payout* path needs a campaign past its end date, and the shortest campaign this canister accepts is one day; `test/e2e.sh` documents how to exercise it with a time-shortened build.

### Important note on stable structures

If you change a `StableBTreeMap`'s configuration — the key or value datatypes, or their sizes — you must restart DFX with `--clean`. A `StableBTreeMap`'s configuration cannot be changed after initialization:

```bash
npm run start:clean
```

## Deploying

The canister takes the ledger's principal as an **init argument** — it is not hardcoded, and the frontend reads it back at runtime via `getLedger`. Verify what a deployment is settling against at any time:

```bash
dfx canister call crowdfund getLedger '()'
```

### Locally

`npm run deploy:local` handles everything (see [Getting started](#getting-started)).

### To mainnet

`dfx.json` marks the ledger and Internet Identity as **`remote`**, so a mainnet deploy does *not* create copies of them — it wires straight to the real ones. Only `crowdfund` and `crowdfund_frontend` are created.

**1. Choose a ledger.** This decides whether contributions cost real money.

| Ledger | Canister id | Notes |
| --- | --- | --- |
| **ckTESTBTC** | `mc6ru-gyaaa-aaaar-qaaaq-cai` | Test bitcoin, **no real value**, ICRC-2 supported, fee 10. No real value, so a bug costs nothing. See the [ckBTC reference](https://docs.internetcomputer.org/references/ckbtc-reference). The right choice for a demo. |
| **ICP** | `ryjl3-tyaaa-aaaaa-aaaba-cai` | **Real money.** Every contribution spends actual ICP. |

**2. Use a secure identity.** The default dfx identity is stored in plaintext, and dfx will warn you about using it against mainnet. Whatever identity you deploy with becomes the canisters' controller:

```bash
dfx identity new mainnet --storage-mode keyring
dfx identity use mainnet
```

**3. Fund it with cycles.** Canisters pay for their own compute and storage in cycles, obtained by converting ICP — see [tokens and cycles](https://docs.internetcomputer.org/building-apps/getting-started/tokens-and-cycles). **There is no free way to keep a canister alive**: cycles are consumed continuously, and a canister that runs out is *deleted*, not merely stopped. Mainnet is an ongoing commitment, not a one-off. (DFINITY has at times offered a free cycles grant to new developers; check the current docs rather than assuming it applies.)

**4. Deploy.**

```bash
dfx deploy --network ic crowdfund --argument '(principal "mc6ru-gyaaa-aaaar-qaaaq-cai")'
dfx deploy --network ic crowdfund_frontend
```

The frontend is then served at `https://<crowdfund_frontend-id>.icp0.io`, and sign-in uses the real Internet Identity automatically — `isLocalReplica` is false on any non-local network, so the agent skips the root-key fetch and points at `identity.ic0.app`.

### Why not the playground

`dfx deploy --playground` **cannot work for this canister.** Azle bundles a JavaScript runtime, so the wasm install payload is ~3.5 MB against the playground's 2 MB limit:

```
application payload size (3517461) cannot be larger than 2097152
```

This is a hard platform limit, not something to tune around. Mainnet has no such restriction — it installs large wasms in chunks.

## Methods

All methods return a `variant { Ok; Err }`, where `Err` is one of `CampaignNotFound`, `ContributionError`, `AuthorizationError`, `ValidationError` or `LedgerError`.

### `createCampaign(payload) -> Result<text>`

Creates a campaign; the caller becomes its owner. Returns the new campaign's id.

- `title` (`text`) — must be non-empty
- `description` (`text`) — must be non-empty
- `goalAmount` (`nat`) — must be positive
- `durationDays` (`nat64`) — 1–365

### `contribute(campaignId, amount) -> Result<text>`

Pulls `amount` from the caller into the canister via `icrc2_transfer_from` and records the contribution. Requires a prior ICRC-2 approval (see above).

A contribution larger than the campaign's remaining need is **capped** at that remainder, and the confirmation reports the amount actually taken — so a campaign cannot get stuck just short of its goal waiting for an exact-fit contribution.

### `withdrawFunds(campaignId) -> Result<text>`

Owner only. Requires the goal to have been reached. Transfers the raised total minus the ledger fee to the owner, and marks the campaign settled so it can only ever pay out once.

### `refund(campaignId) -> Result<text>`

Refunds **the caller's own** contributions, once the campaign has expired below its goal. Scoped to the caller so the work stays bounded no matter how many backers a campaign has.

### `deleteCampaign(campaignId) -> Result<text>`

Owner only. Deletes the campaign and its contribution history. Refuses while the canister still holds the campaign's tokens — withdraw or refund them first.

## Interacting with the canister

Use the command line, or the Candid web interface linked in the deploy output. Note that only `createCampaign` takes a record — the rest take **positional arguments**:

```bash
# Create a campaign: goal 1,000,000 tokens, running 30 days
dfx canister call crowdfund createCampaign \
  '(record {title = "Campaign Title"; description = "Campaign Description"; goalAmount = 1_000_000 : nat; durationDays = 30 : nat64})'

# Approve the crowdfund canister to spend on your behalf, then contribute
dfx canister call <ledger> icrc2_approve \
  "(record {spender = record {owner = principal \"$(dfx canister id crowdfund)\"}; amount = 100_010 : nat})"
dfx canister call crowdfund contribute '("0", 100_000 : nat)'

dfx canister call crowdfund withdrawFunds '("0")'
dfx canister call crowdfund refund '("0")'
dfx canister call crowdfund deleteCampaign '("0")'

dfx canister call crowdfund getCampaign '("0")'
dfx canister call crowdfund getCampaigns '()'
dfx canister call crowdfund listContributions '("0")'
```

Shut the local replica down with:

```bash
npm run stop
```

## Implementation notes

**Inter-canister calls and concurrency.** Every `await` on a ledger call is a commit point — other messages run before the response arrives, so any check made before the await is stale afterwards. The canister therefore mutates state *synchronously first* (reserving a contribution against the goal, flagging a withdrawal), then calls the ledger, then undoes that mutation if the call fails. This is what stops two concurrent contributions from both overshooting the goal, and two concurrent withdrawals from both paying out.

**Campaign ids** come from a stable counter rather than uuid v4. Azle seeds its `Math.random` deterministically, so v4 ids are predictable on ICP and can collide.

## History

This project was originally written against Azle 0.20 and was archived in 2026 after its dependencies became uninstallable: Azle 0.20 pulled Candid from `github:demergent-labs/candid#minimum_viable`, npm resolved that over SSH, and the branch was subsequently deleted upstream — leaving the pinned commit unreachable and the tree impossible to install from a clean clone. It has since been migrated to Azle 0.33, whose decorator-based API replaces the old `Canister({...})` style, and the funds layer — which previously only incremented a counter and never moved any value — was implemented against a real ICRC ledger. The current tree installs, typechecks, builds to wasm and passes its end-to-end suite against a live local ledger.
